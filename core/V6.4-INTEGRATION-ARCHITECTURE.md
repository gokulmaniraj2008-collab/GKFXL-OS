# GKFXL OS v6.4 Integration Architecture

## Purpose
Integrate the Reality & Evaluation capabilities into one closed-loop operating architecture instead of treating them as isolated modules.

## Integrated Control Loop

Mission → Context → Decision → Action → Observation → Reality Grounding → Reality Feedback → Outcome Attribution → Confidence Calibration → Regression/Drift Check → Learning Quality Check → Prediction-to-Outcome Memory → Benchmark → Next Decision

## Cross-Layer Responsibilities

### 1. Mission & Context
Mission Control defines objective, success criteria, constraints, risk, and next best action. Context Engine supplies only the minimum accurate context required for the next decision.

### 2. Decision & Execution
Decision Engine selects an action using evidence, risk, reversibility, confidence, and expected learning value. Autonomous Work Loop executes safe, bounded steps and requires verification before completion claims.

### 3. Reality Gate
Reality Check Engine and Reality Grounding Gate classify claims as Observed, Supported, Inferred, Assumed, or Unknown. Consequential decisions cannot silently promote assumptions to facts.

### 4. Feedback & Attribution
Reality Feedback Engine compares predictions/actions with observations. Outcome Attribution Engine evaluates competing explanations and assigns attribution confidence rather than assuming causation.

### 5. Evaluation
Confidence Calibration measures prediction reliability. Regression Intelligence checks whether changes damage existing capabilities. Drift Detection checks whether the environment, data, requirements, or outcomes have changed. Capability Benchmarks measure repeatable performance.

### 6. Learning
Learning Quality Controller checks whether a lesson is trustworthy. Prediction-to-Outcome Memory preserves the original prediction, confidence, action, observed outcome, error, evidence, attribution, and lesson for future calibration.

## Evidence Contract

Every consequential claim should have:

- Claim
- Evidence
- Freshness
- Verification state
- Confidence
- Known uncertainty
- Expected consequence if wrong

## Decision States

- **PASS** — evidence is sufficient and the action is acceptable.
- **HOLD** — more evidence or verification is required.
- **REJECT** — evidence or safety conditions are insufficient.
- **ESCALATE** — uncertainty or consequence exceeds the system's safe operating boundary.

## Anti-Loop Rule

The OS must not repeatedly collect evidence without changing a decision, reducing uncertainty, or increasing outcome quality. Evidence gathering must have a decision purpose.

## Upgrade Rule

A new capability is accepted only when it improves the integrated system without unacceptable regression, security weakness, unnecessary complexity, or loss of reality grounding.

## Principle

**GKFXL OS is not a collection of AI features; it is a closed-loop evidence-to-outcome operating system.**
