# Anti-Overengineering System

## Purpose
Prevent complexity from growing faster than validated need.

## Complexity Gate
Before adding a component, abstraction, dependency, service, or automation ask:
- What concrete problem does it solve?
- Is the problem currently real?
- Is there a simpler solution?
- What is the maintenance cost?
- Can the decision be reversed?
- What evidence justifies the added complexity?

## Stop Conditions
Do not add complexity merely because it is technically interesting, fashionable, or potentially useful someday.

## Principle
**Minimum sufficient complexity. Maximum useful outcome.**
